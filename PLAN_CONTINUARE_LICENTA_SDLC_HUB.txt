2. CE NU ESTE IMPLEMENTAT SAU ESTE DOAR PARTIAL

2.1. Metodologii si tranzitii SCRUM/KANBAN/SCRUMBAN
Stadiu actual:
- Metodologia exista pe Project.
- Sidebar-ul ascunde Backlog pentru KANBAN.
- Backend-ul blocheaza trecerea la KANBAN daca exista sprint activ.
- Create Issue ascunde story points pentru KANBAN.
- Sprint endpoints blocheaza sprinturile pentru KANBAN.

Ce lipseste:
- Nu exista inca un "Methodology Transition Wizard" real.
- Nu exista preview al impactului cand schimbi metodologia.
- Nu exista reguli complete pentru migrarea datelor intre moduri:
  - SCRUM -> KANBAN: ce se intampla cu backlog-ul, sprinturile viitoare si task-urile din sprinturi inactive.
  - KANBAN -> SCRUM: cum se creeaza primul backlog/sprint si ce task-uri intra unde.
  - SCRUM -> SCRUMBAN: se pastreaza backlog-ul si sprinturile, dar executia trebuie sa fie mai flexibila.
  - SCRUMBAN -> SCRUM: trebuie verificat daca exista task-uri neplanificate care ar trebui mutate in backlog.
- Nu exista adaptare automata a rolurilor la schimbarea metodologiei:
  - Scrum Master pentru SCRUM.
  - Flow Manager pentru KANBAN.
  - ambele sau un hibrid pentru SCRUMBAN.
- Nu exista audit log pentru schimbarea metodologiei la nivel de proiect.
- Nu exista confirm modal specific pentru schimbarea metodologiei, cu explicatii si pasi.
- Nu exista inca un document complet de verificare manuala pentru aceste tranzitii.
